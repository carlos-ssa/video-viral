# Fluxo 3D do stack

Blender modela/anima e renderiza; Three.js integra cenas 3D web ao tempo do HyperFrames. Blender MCP automatiza o Blender já configurado; seu repositório canônico é ahujasid/mcp-for-blender. Setups antigos podem continuar funcionando; não reconfigurar o cliente sem necessidade.

## Antes da cena: referências e ativos

Ao criar/compor uma cena ou sequência, siga [câmera e pacote visual](../camera-references.md) antes do blockout. Pesquise o estilo em filmes, séries, vlogs ou demonstrações pertinentes; a IA inspeciona as fotos/trechos disponíveis e entrega arquivos, observações e decisões por plano ao executor Blender. Um prompt com o nome de um filme não substitui esse material. Procure [itens 3D gratuitos](../free-3d-assets.md) compatíveis antes de modelar; confirme licença por item e teste escala, materiais e custo da cena.

Use um arquivo de trabalho separado ao experimentar, preservando o projeto do usuário. Confirme que o processo Blender/MCP acessa os caminhos reais; se estiver em outra máquina, transfira apenas a mídia necessária por mecanismo autorizado, sem presumir que caminhos locais funcionam remotamente. Pacote sem arquivos acessíveis fica pendente, não «carregado».

## Referências no arquivo de trabalho

A referência tem dois usos distintos: **a IA vê a mídia e a interpreta**, depois **o Blender a abre como apoio visual**. Importar uma imagem não cria geometria nem faz o Blender entender automaticamente um estilo. O catálogo atual não promete reconstrução image-to-3D ou geração de vídeo por esse carregamento.

- Fotos/frames: carregar como imagens de referência (Empty/Image), fundos de câmera ou painel de comparação, em coleção de estudo fora do render. Identificar IDs do pacote em cada objeto. Comparar enquadramento/escala/luz no blockout antes do detalhe.
- Vídeos: abrir o trecho no Movie Clip Editor e comparar início/meio/fim e movimento quando houver capacidade temporal. Se a integração só aceitar imagens, carregar frames extraídos com timecodes e deixar a trajetória não verificada; não declarar que o vídeo inteiro foi analisado. Não colocar a referência na montagem final por acidente.
- Várias cenas: compartilhar a bíblia e os IDs, mas mapear quais referências orientam cada plano. Preservar eixo de ação, escala de personagens/objetos, lente/altura e iluminação; justificar desvios. Salvar câmera, rig/alvo, keyframes, foco e curvas, além da descrição em texto.

Exemplo de carregamento via `bpy`, no arquivo de trabalho, para o contrato de `research/reference-pack.json`. Ajuste `PROJECT` ao projeto absoluto. Valida todos os arquivos/hashes antes de criar a coleção; não apaga a cena, não anima, não empacota mídia e não salva por cima do `.blend` do usuário:

```python
from pathlib import Path
import hashlib
import json
import bpy

PROJECT = Path("/caminho/absoluto/do/projeto").resolve()
pack = json.loads((PROJECT / "research/reference-pack.json").read_text(encoding="utf-8"))
checked = []
for ref in pack["references"]:
    for media in ref.get("media", []):
        path = (PROJECT / media["path"]).resolve()
        if not path.is_relative_to(PROJECT) or not path.is_file():
            raise ValueError(f"Referência inacessível ou fora do projeto: {media['path']}")
        digest = hashlib.sha256()
        with path.open("rb") as source:
            for chunk in iter(lambda: source.read(1024 * 1024), b""):
                digest.update(chunk)
        if digest.hexdigest() != media["sha256"].strip().lower():
            raise ValueError(f"SHA256 divergente: {media['path']}")
        if media["kind"] not in ("image", "video"):
            raise ValueError(f"Tipo de referência não suportado: {media['kind']}")
        checked.append((ref["id"], media["kind"], path))

if not checked:
    raise ValueError("O pacote não contém fotos/frames ou vídeos locais")
refs = bpy.data.collections.new("VV_STUDY_REFERENCES")
refs["video_viral_reference_only"] = True
refs.hide_render = True
bpy.context.scene.collection.children.link(refs)
for index, (ref_id, kind, path) in enumerate(checked):
    if kind == "image":
        image = bpy.data.images.load(str(path), check_existing=True)
        image.reload()
        obj = bpy.data.objects.new(f"VV_REF_{index:03d}", None)
        obj.empty_display_type = "IMAGE"
        obj.data = image
        obj.location = (index * 2.0, 0, 0)
        obj.hide_render = True
        obj["reference_id"] = ref_id
        refs.objects.link(obj)
    else:
        clip = bpy.data.movieclips.load(str(path), check_existing=True)
        clip.use_fake_user = True
        clip["reference_id"] = ref_id
        clip["video_viral_reference_only"] = True
        print("Referência carregada para Movie Clip Editor:", clip.name, clip.frame_duration)
print("Pacote de estudo carregado:", len(checked), "arquivos")
```

Confira dimensões/duração e o resultado no arquivo real; selecione o clip carregado no Movie Clip Editor para examiná-lo. `use_fake_user` preserva o datablock de vídeo ao salvar/reabrir mesmo sem um editor associado; não empacota o arquivo. Sucesso no console não comprova interpretação visual. Esse trecho foi validado tecnicamente no Blender 5.3 com mídia sintética de teste, incluindo salvar/reabrir, sem avaliar estilo ou movimento de filmes. Em outra versão, confira as APIs disponíveis antes de executar. Referências oficiais: [imagens](https://docs.blender.org/api/current/bpy.types.BlendDataImages.html), [movie clips](https://docs.blender.org/api/current/bpy.types.BlendDataMovieClips.html) e [referências de viewport](https://docs.blender.org/manual/en/latest/modeling/empties.html).

Guarde o pacote e o `.blend` de estudo para retomada. Referências `study_only` não devem aparecer nos pixels finais, ser exportadas como geometria/texture ou ser empacotadas/distribuídas sem direito correspondente. Quando entregar um `.blend`/GLB, faça uma cópia limpa sem mídia de estudo não autorizada, preservando o arquivo de trabalho; `hide_render` sozinho não remove dados do arquivo entregue. Ativos efetivamente incorporados seguem `assets[]`, licença e atribuição. Prévia de viewport pode mostrar overlays de estudo; conferir também o render da câmera.

## Câmera, teste e composição

Traduza o plano para câmera/rig/alvo e geometria com profundidade: deslocamento real para dolly/tracking, rotação para pan/tilt, lente para zoom e foco para rack focus. Defina sensor/aspecto, unidade/escala e alvo; valores escolhidos não são medições da lente do filme. Ruído de handheld/ações simuladas precisa ser limitado, fixado por seed/cache e estável ao buscar frames fora de ordem.

Teste blockout, três posições da câmera e um preview curto antes de renderizar várias cenas. Conferir oclusões, clipping, foco, continuidade de eixo e transição; sem percepção temporal, manter esse canal pendente. Detalhes e registro por plano em [câmera](../camera-references.md#testar-antes-da-sequência-inteira).

Para repetição, salvar fonte .blend ou script bpy e os parâmetros. Uma chamada bem-sucedida ao MCP não prova que a cena renderizou corretamente. É possível validar scripts em Blender headless sem alterar a sessão gráfica do usuário.

Exportar GLB para Three.js quando os recursos forem compatíveis e conferir materiais/animações. Usar glTF Transform para preparar o ativo. Um render do Blender também pode entrar no HyperFrames como vídeo/frames, com transparência apenas em formato compatível. Preservar origem e parâmetros para refazer o trecho.

Luz, câmera, material e movimento devem acrescentar informação à peça. Não transformar screenshots de produto em prova falsa; gráficos/objetos conceituais precisam ser distinguíveis da interface real.
